## 记录

### 2026-11-07 · `npx skills add <repo>` 会安装整仓库，而非单个技能

- 现象：执行 7 条 `npx skills add` 命令后，`.agents/skills/` 出现 100 个技能目录，
  远超预期。
- 根因：`skills` CLI 的 `add` 子命令以 **GitHub 仓库**为单位安装，仓库内所有
  `SKILL.md` 都会被登记，不支持按单个技能名筛选。
- 处理：改为安装后再按白名单精简，并让 `skills-lock.json` 与实际保留目录对齐。
- 验证方式：比对 `skills-lock.json` 条目数与四个技能目录的实际条目数。
- 尚未验证：精简后各技能在 Claude Code 与 Codex 两侧的加载是否完全一致。

### 2026-11-07 · 技能目录的软链接不能用 `rm -rf` 清理

- 现象：`skills/`、`.claude/skills/` 下的条目是软链接（`lrwxrwxrwx`），直接
  `rm -rf` 有连带删除 `.agents/skills/` 真实内容的风险。
- 根因：真实目录集中在 `.agents/skills/`，另两个目录只是链接视图。
- 处理：软链接一律用 `unlink`（只删链接本身）；仅对 `.agents/skills/` 与
  `agent/skills/` 这类真实目录使用递归删除。清理顺序为先链接目录、后真实目录。
- 验证方式：清理后逐个目录统计断链数，要求全部为 0。
- 尚未验证：Windows 上「目录型」软链接的 `unlink` 行为在不同 Node 版本下的差异
  （已加 `EPERM` 兜底退回 `rmSync`）。
